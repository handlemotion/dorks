## 2. Hardening findings (file:line)

"Repro" means demonstrated in this sandbox. The convex-test repros are in `docs/repros/lifecycle-races.test.ts` (copy them into `apps/convex/test/` to run; both pass today, which means the bugs are real).

### Lifecycle
- **H1 (high, repro): a healthy dork goes to `error` after a bridge blip.** `lifecycle.ts:31-40` (`bridge_watch`) sets `bridgeLost` and arms the 3-minute watchdog. `bridge.ts:136` (`push`) and `bridge.ts:35` (`connect`) clear `bridgeLost` without dispatching `agent_ready`. Only `heartbeat` (`bridge.ts:67`) cancels the watchdog, and only if it still sees `bridgeLost === true`. A bridge that recovers by pushing buffered events first, which is the normal case mid-turn, leaves the watchdog armed, and 3 minutes later the dork is killed with "timed out waiting for the sandbox". Fix: handle the lost→found transition in one helper called from `push`/`heartbeat`/`connect` (if `rt.bridgeLost` and the state is working/idle, dispatch `agent_ready`).
- **H2 (high, repro): a message sent while a sleep-pause is in flight pauses the box under a live turn.** `sleep_due` → `beginPause` (`lib/dispatch.ts:137`) enqueues `flush` but leaves the state `idle`. A user message moves it to `working`. Then `flushed` → `finishPause` → `boxes.pause` → `boxPaused` → machine `paused` accepts any AWAKE state (`machine.ts:98`) → `sleeping` mid-turn. The same happens via the flush timeout (`lifecycle.ts:28`). With a real bridge the window is the flush plus the Upstash pause latency (seconds), so it's hit routinely. Fix: record a pause intent (`rt.pausing` epoch). In the `user_message`/`archive` paths, cancel the flush timer and delete the flush command. `finishPause`/`boxPaused` must check that the intent is still current; if it isn't, resume or ignore.
- **H3 (med): no recovery when the provider loses a box.** `boxes.resume` (`boxes.ts:52`) fails → `error` → the next message → `waking` → resume fails again, forever. A deleted/expired paused box (Upstash retention) bricks the dork. Fix: on "box not found", clear `boxId` so `error` + message takes the `create_box` path (`machine.ts:74`), resuming the Claude session from `claudeSessionId` if the session state lives outside the box; otherwise start fresh.

### Auth
- **H4 (med, repro): no rate limit on OTP send/verify.** 25 sends to one `@jaantonio.com` address in a loop → 25/25 delivered. Verify is capped at 3 wrong guesses per code (then `TOO_MANY_ATTEMPTS`), but requesting a new code resets that. Anyone can mail-bomb a colleague and burn the Resend quota, and a 6-digit brute force costs ~1M/3 sends with no throttle. Better Auth's built-in rate limiter is in-memory and doesn't hold across Convex isolates. Fix: `@convex-dev/rate-limiter` (or a small table) checked in `hooks.before` (`auth.ts:24`), keyed per email and per IP.
- **H5 (low): `trustedOrigins`** (`auth.ts:23`). An unset `SITE_URL` is filtered out by better-auth, so there's no crash, but cross-domain web sign-in then fails silently; fail fast at module load. On-device dev with Expo Go sends `exp://…` origins, which aren't trusted (only `dorks://`). Needs a dev-only entry.

### Secrets / bridge auth
- **H6 (high, cheap): the GitHub token handed to the box isn't scoped to the repo.** `apps/api/src/lib/github.ts:31` POSTs `/access_tokens` with no body, so the token covers every repo and every permission of the installation. That token sits in a box where Claude runs arbitrary commands on untrusted repo content (prompt injection), so it can write to every repo the user installed the App on. Fix: send `{ repositories: [name], permissions: { contents: "write", pull_requests: "write" } }` from `bridge.configure`/`ghToken`.
- **H7 (low): the bridge secret is permanent and readable by the agent.** `BRIDGE_SECRET` is in the box env (`boxes.ts:27`), so the agent can read it, push forged transcript events or call `bridge.configure`. Blast radius is that one dork and secrets the box already has, which is acceptable for v1. It doesn't rotate (`lib/bridgeAuth.ts:12`, no version in the HMAC input). Per the comment in `boxes.ts`, the create-time env is frozen into snapshots made from that box. Fix later: version the HMAC input (`bridge|v1|dorkId`) and strip the env before user snapshots.
- **H8 (low): no key rotation** for `ENCRYPTION_KEY` (`crypto.ts` keyring has only v1, from env) or `BRIDGE_SECRET_KEY`. The envelope format already supports versions; only `keyringFromEnv` needs to read `ENCRYPTION_KEY_V2`.

### Input validation / limits
- **H9 (med): `bridge.push` takes `v.array(v.any())`** (`bridge.ts:72`) with no cap on frame count or size. Events are only zod-validated per frame. A runaway or hostile bridge can write huge rows (1MB doc limit → mutation failure → the bridge drops the batch after 5 retries, `convex-sim.mjs:45`, which means **silent transcript loss**). Fix: cap frames per call and bytes per event, truncate tool output in the normalizer, and have the bridge split batches instead of dropping them.
- **H10 (low): unbounded user inputs.** `setClaudeToken` has no length cap (`settings.ts:28`). `setCliSecret` has no value-size or count cap (`settings.ts:38`), and all secrets get decrypted into the box env. `setSleepMinutes` lets `NaN` through `Math.min/max` (`settings.ts:91`). `runAfter(NaN)` then throws inside `arm_sleep`, which rolls back every `push` batch containing `turn_idle`. The bridge drops the batch, the dork is stuck in `working` and the box never sleeps. That makes this **medium**, and it's one line to fix (`Number.isFinite`). `create` doesn't cap the number of dorks per user, and each one creates a billable box.
- **H11 (low):** `events.list` doesn't check `deleting` (`events.ts:16`; `dorks.get` does). Acked `user_message` command rows are never deleted until purge, so `queued()`/`ack` scans stay small but the table grows. Expected `ConvexError`s are logged as "Uncaught" (log noise).

### Second review pass (independent agent, traced in code; I confirmed R1 and R2 by reading)
- **R1 (high): `error` never pauses the box, so it leaks billing.** `machine.ts:107` sends `agent_exited`/`op_failed`/`watchdog` → `error` with `STOPPED` (no `pause_box`), and `bridge_watch` stops re-arming once the dork isn't awake (`lifecycle.ts:31-40`). Any agent crash, configure failure or watchdog leaves the box running with no timer that will ever stop it. Fix: `pause_box` (when `hasBox`) on entering `error`.
- **R2 (high): stale control rows replay into the next wake.** Non-message commands are deleted only on ack (`bridge.ts:121`). If the flush *timeout* path paused the box (`lifecycle.ts:28`), the `flush` row survives, `bridge.commands` re-emits it in `waking`, and the new bridge flushes → pause → `sleeping` with the user's message still queued. Leftover `interrupt` rows likewise kill the first turn after a wake. Fix: delete non-message command rows on `paused` and on `create_box`/`resume_box`.
- **R3 (med): "acked" isn't the same as "turn done".** `queued` (`machine.ts:92`) only counts *unacked* messages, and the bridge acks on receipt. If a steering message is acked mid-turn, turn 1's `turn_idle` moves the dork to `idle` and arms sleep while turn 2 is running. There's also no inactivity timeout in `working`, so a hung agent keeps its box forever. Fix: the bridge reports turn start/end; add a `working` inactivity watchdog.
- **R4 (med): a dropped batch leaves a permanent transcript gap.** `bridgeSeq` jumps to the highest `bseq` seen (`bridge.ts:95`), and the sim drops a batch after 5 failures (`convex-sim.mjs:45`), so those events never come back. A hostile bridge can also push `bseq = 2^53` to mute the dork. Fix: require `bseq === bridgeSeq + 1` and return the expected seq so the bridge replays; the bridge must never drop.
- **R5 (med): `opFailed` isn't tied to the operation that failed** (`lifecycle.ts:46`). A slow resume that lost to the watchdog, followed by a user retry, makes the stale failure flip the new attempt to `error`. A transient GitHub 5xx in `configure` on an ordinary reconnect also kills a healthy dork. Fix: an op generation on `dorkRuntime`; ignore stale failures. Retry `configure`'s GitHub call.
- **R6 (med): the deleting window drops timers.** `lifecycle.timer` returns early while `deleting` without re-arming. If the box delete fails, `unmarkDeleting` (`dorks.ts:113`) brings the dork back with no watchdog/bridge_watch. If the `destroy` action crashes (actions are at-most-once), `deleting` stays true forever: the dork is invisible, can't be removed again, and the box leaks. Fix: reconcile in `unmarkDeleting`, plus a cron sweep for old `deleting` rows.
- **R7 (low): a failed GitHub token refresh retries too late.** `lifecycle.ts:23-26` always re-arms at 45 min, so a failed refresh retries at 90 min, after the 60-min token has expired. Also, `configure`/`ghToken` mint tokens regardless of state (asleep or archived). Fix: retry in 1–5 min on null; refuse unless the dork is awake.
- **R8 (low): `REPO` (`dorks.ts:9`) accepts `../..`,** and nothing checks the repo belongs to the installation. Web `Thread` (`apps/web/src/routes/dorks.tsx:79`) has no `key`, so a typed draft survives switching dorks and gets sent to the newly selected one. Create/Send aren't disabled while pending, so a double-click creates two boxes.
- **R9 (low, unverified): AES-GCM IVs are generated inside mutations** (`settings.ts:34,43`). Confirm that Convex's in-mutation `crypto.getRandomValues` isn't a replay-seeded PRNG, or move encryption into an action.
- Checked and fine: HMAC parse/verify is constant-time; an unset `ENCRYPTION_KEY` fails closed; `push` is atomic (no partial batches); OTP verify-consume is atomic.

## 4. Decision points

1. **Convex vs. the Cloudflare `apps/api` path.** Both are now on `main`. The spike answered the hard questions: auth, reactive replay, atomic lifecycle, secret isolation. Everything left on the critical path (bridge, box provider, onboarding, webhook, push) is *backend-agnostic in substance*. Its *integration* is Convex-specific, though (the bridge talks to Convex functions rather than a DO WebSocket), so it shouldn't be built twice. **Recommendation: commit to Convex now, freeze `apps/api` (no new work), delete it once P0 is done.** Things that could reverse this, and how to learn each cheaply:
   - *DB bandwidth with real turns.* The spike's 1GB/month free-tier line is a sim estimate. Measure `usage.mjs`-style numbers on the first real-bridge turns (P0-5). Levers are ready: page size 40→20, a bigger `DELTA_BATCH_MS`, a separate live-text doc. The cost ceiling is a few $/month on Starter, so this decides *configuration*, not *backend*.
   - *better-auth pinned to 1.6.x* by `@convex-dev/better-auth` 0.12.5. Fine for emailOTP. Re-check when you need a 1.7-only feature.
   - *Lock-in.* The self-hosted backend ran everything here, so an exit path exists.
2. **How the bridge reaches the backend.** The spike's design has the box run a Convex client (outbound WebSocket to `*.convex.cloud`), with secrets fetched via actions. That needs outbound access to Convex from the box. If you use Upstash `network_policy` to lock egress down, allow-list Convex, GitHub, Anthropic and npm.
3. **Upstash Box semantics** (decide before writing the provider): does pause keep processes alive (memory snapshot) or restart them, and is `init_command` re-run on resume? Does `init_command` need keep-alive/paid? How long are paused boxes retained (drives H3)? Is create idempotent (labels)? One hour with the API and a throwaway box answers all four.
4. **Where Claude session state lives.** `--resume <id>` needs `~/.claude` on the box disk. If boxes can disappear (H3), decide whether losing the session on re-create is acceptable for v1 (probably yes: the repo state is on the branch).
5. **Bandwidth/UX knobs:** page size and delta batching. Decide from measured real turns, not now.
