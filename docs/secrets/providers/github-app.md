# GitHub App (repo access for boxes + install verification)

Provides: `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY` (`shared`); `GITHUB_APP_CLIENT_ID`, `GITHUB_APP_CLIENT_SECRET` (`convex`); `GITHUB_WEBHOOK_SECRET` (`shared`, **generated by us**, you paste it into GitHub).

Official docs (checked 2026-10-07): [Registering a GitHub App](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app), [Managing private keys](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/managing-private-keys-for-github-apps), [User access tokens / client secret / installation OAuth](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app).

## Dev vs prod

GitHub Apps have no test mode. Register **two apps**: `dorks-dev` (callback to `http://localhost:3000/...`) and `dorks` (prod). While `BOX_PROVIDER=sim` the dev app is never contacted (the code short-circuits), so the dev entries can stay dummy until you test the real flow. Own the prod app by an organization, not a person, so it survives people leaving.

## 1. Register the app

1. GitHub -> profile picture -> **Settings** (or **Your organizations -> Settings** for an org) -> **Developer settings** -> **GitHub Apps** -> **New GitHub App**.
2. Name (<= 34 chars, globally unique), Homepage URL = the web origin.
3. **Callback URL**: the web page that handles the install redirect (the web origin plus the route that calls `settings.linkGithubInstallation`; that route does not exist yet, so set it when it does).
4. Tick **Request user authorization (OAuth) during installation**. The code (`apps/convex/convex/lib/githubInstall.ts`) exchanges the returned `code` and rejects installation IDs the user cannot see. This option removes the Setup URL field; that is expected. Leave **Expire user authorization tokens** on.
5. **Webhook**: Active on. URL = the Convex site URL's webhook route (planned; use a placeholder until it exists). **Webhook secret**: print it locally with `pnpm exec dotenvx get GITHUB_WEBHOOK_SECRET -f secrets/.env.<env>` (do not paste it anywhere but GitHub's field; needs that env's key). SSL verification on.
6. Permissions (inferred from code: installation tokens for repo access and `pull_request` events; review against the final box workflow): Repository **Contents: Read & write**, **Pull requests: Read & write**, **Metadata: Read-only**. Subscribe to **Pull request**.
7. **Where can this app be installed?** Prod: **Any account** if users install on their own orgs, otherwise **Only on this account**.
8. **Create GitHub App**.

## 2. Collect the four values

On the app's settings page (**Developer settings -> GitHub Apps -> Edit**):

- **App ID** (top of **General**) -> `GITHUB_APP_ID`.
- **Client ID** (also on **General**; different from the App ID) -> `GITHUB_APP_CLIENT_ID`.
- **Client secrets -> Generate a new client secret** -> `GITHUB_APP_CLIENT_SECRET` (shown once).
- **Private keys -> Generate a private key** (a.k.a. Credentials -> Key pairs -> New key) downloads a `.pem`. GitHub gives **PKCS#1** (`BEGIN RSA PRIVATE KEY`); this codebase requires **PKCS#8** (`apps/api/src/lib/github.ts` rejects PKCS#1). Convert:
  ```sh
  openssl pkcs8 -topk8 -nocrypt -in downloaded.pem -out app.pkcs8.pem
  ```
  Keep the file out of the repo; delete both after inserting.

## 3. Insert

```sh
E=prod   # or dev
scripts/set-secret.sh $E GITHUB_APP_ID
scripts/set-secret.sh $E GITHUB_APP_CLIENT_ID
scripts/set-secret.sh $E GITHUB_APP_CLIENT_SECRET
scripts/set-secret.sh $E GITHUB_APP_PRIVATE_KEY < app.pkcs8.pem   # multi-line PEM via stdin
shred -u app.pkcs8.pem downloaded.pem 2>/dev/null || rm -f app.pkcs8.pem downloaded.pem
```

Rotation: generate the new key, update `secrets/` and the Convex deployment, then delete the old key in GitHub (apps can hold up to 25 keys; they never expire).
