---
title: "Pull requests"
description: "The agent carries each PR from opened to shipped."
---

A session doesn't stop at "task done". It opens pull requests, subscribes to them and keeps working until each one is merged or closed.

## What wakes the agent

- **CI fails.** The agent reproduces the failure, runs the checks locally and pushes a fix. After two failed fixes in a row it stops and leaves a comment asking for a human.
- **A review or comment** from someone your comment policy allows (everyone by default, or an allowlist of logins, bots included).
- **A merge conflict** or a stacked PR whose base moved: it rebases and fixes it.

When a PR is ready, the agent asks you to merge it: a card in the chat with the PR, a short note and **Merge** / **Not now**. Merge merges the commit the agent asked about, never a later push. Your answer goes back to the agent, so it carries on: it follows the merge to production, or fixes what GitHub refused and asks again. **It merges by itself only when you tell it to**: say "merge the PR" in the chat and it merges it, no card. You can also merge from the PR tab (squash, merge or rebase, pinned to the commit you reviewed), or on GitHub.

## Shipping

A merged PR isn't a shipped one. After a merge to the default branch, the chat shows a **Ship** card that follows the merge commit: workflow runs, migrations, other apps' checks (Vercel, Cloudflare, Netlify…) and deployments. When the deploy finishes, the agent checks the change on the live URL. If the ship fails, it opens a fix-forward or revert PR.

## Subscribing to other PRs

Any session can follow a PR it didn't open: subscribe from the chat, and the agent treats it like its own.
