# Site agent notes

`dorks.build`: the marketing site (Astro, static) and the edge Worker `dorks-site` that serves it. The docs are `apps/docs` (Mintlify), served at `/docs` by this Worker. The relay is a separate Worker, `dorks-cloud`, on `api.dorks.build`.

- `src/pages`, `src/layouts`, `src/components`: the site (Astro + React + Tailwind v4). Self-contained UI primitives in `src/components/ui` are built on `@base-ui/react` and `class-variance-authority` (shadcn pattern) and restyled for the marketing site: self-hosted Geist Sans and Geist Serif (`public/fonts`), full-bleed photographic hero, pill-shaped controls, logo-blue (`#0e6fff`) text selection, and Lenis smooth scrolling initialized in `Base.astro`.
- `/login` and `/invite/<id>` (`src/components/SignIn.tsx`): Dorks Cloud sign-in, Better Auth against the relay from the browser (`src/lib/cloud.ts`; `PUBLIC_CLOUD_URL` at build or dev time points it at another relay, such as `http://localhost:8787` from `wrangler dev` with `DEV=1`). `?next=` may only go to dorks.build or api.dorks.build.
- `/onboarding` (`src/components/Onboarding.tsx`, `src/lib/onboarding.ts`): a new Dorks Cloud team in the browser: workspace, plan (Stripe Checkout trial), invites, Boat, agents, each saved to the relay as it is answered, so a reload resumes at the first open step. It draws with the desktop's onboarding pieces (`@dorks/onboarding` on `@dorks/ui`, `src/styles/onboarding.css`). Opened by the desktop (`/login?next=/onboarding&app=1&state=<nonce>`; `/login` carries `app` and `state` on), it ends with `POST /v1/app-handoff` and `dorks://auth?code=&state=`. The relay must allow dorks.build's CORS on `/v1/orgs*` and `/v1/billing/*` too.
- `src/worker.ts`: the edge. www redirects to the apex, `/download` 302s to the latest release's `.dmg` (`/download/<version>` for one version, `/download.json` for the buttons' version and size; GitHub's API, cached in the colo for 5 minutes, `src/lib/release.ts`), `/invite/<id>` serves the one invite page, `/docs`, `/_mintlify/*` and `/mintlify-assets/*` go to Mintlify (`DOCS_HOST`), the rest is `env.ASSETS`. `DOCS_PROXY` is `"true"` (Mintlify has the custom domain `dorks.build` with base path `/docs`); `"false"` would redirect `/docs` to `DOCS_HOST` instead.
- `pnpm --filter @dorks/site dev` for the site alone, `preview` to run the built site behind the Worker on `wrangler dev`, `deploy` to ship by hand (needs a Cloudflare login on the Handle account). Normally you don't: Cloudflare Workers Builds deploys `dorks-site` on every push to `main` that touches `apps/site/` or the lockfile (trigger "Deploy dorks.build from main", root `apps/site`, `pnpm run build` then `npx wrangler deploy`).
- Astro's guides: https://docs.astro.build. Run `astro dev --background` (and `astro dev stop`) when starting the dev server from an agent.
